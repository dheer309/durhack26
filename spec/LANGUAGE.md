# Prototype physical language, version 2

The watermark is applied to each page of an existing PDF. A 32-bit recipient ID and its CRC-32 checksum form eight bytes; eight Reed–Solomon parity bytes produce 128 bits. The payload is repeated six times across 768 seed-shuffled, slightly jittered positions. A single grey dot at one of two positions represents each bit. Coordinates are proportional to the displayed page; all shared parameters are in `config.py`. The same input PDF bytes and ID produce the same marked PDF bytes.

Four distinct corner patterns are drawn. The current decoder does **not** detect them: it searches for the page boundary, rectifies the page, tries four orientations, combines repeated samples and requires both successful Reed–Solomon decoding and a valid CRC. Weak signals and failed checks are rejected; the reported signal agreement is not a probability of a correct result. CRC is an accidental-error check, not authentication.

The dots are approximately 0.92 mm in diameter on A4 and use grey with partial opacity. This is slightly larger than the initial 0.3–0.8 mm range. The jittered pattern still originates from a grid and has not been tuned for stealth or tested with a physical printer and phone. The public seed is not a secret key. The decoder also has a conservative compatibility path for near-upright, tightly cropped version 1 screenshots. Version 1 has no checksum, so this path requires strong repeated-bit agreement and limited error correction; it cannot offer the same validation as version 2. See `eval/` for controlled synthetic results and their limits.
